# 登录状态如何保存

## 使用效果

Web 版的使用方式与普通网站一致：登录并完成首次改密后，刷新页面、关闭标签页后重新打开，
或者 Web 界面服务重启后重新访问，同一浏览器仍会自动恢复登录。用户主动点击“退出登录”后，
本地登录记录和服务器上的对应凭据都会失效，再次打开页面必须重新输入用户名和密码。

默认有效期是 30 天。这里的 30 天从每次服务器签发新的登录凭据开始计算；恢复登录时，服务器
会撤销旧凭据并签发一个新的凭据。管理员可通过 `DEFENSE_REFRESH_TOKEN_DAYS` 修改天数。

以下情况不会自动恢复登录：

- 用户主动退出；
- 管理员停用账号或重置密码；
- 用户修改密码，其他设备上的旧凭据同时失效；
- 登录记录超过有效期；
- 用户清除了该站点的浏览器数据；
- 使用无痕窗口后关闭了该窗口。

## 保存了什么

Web 版只在当前浏览器配置中保存可撤销、会轮换的刷新凭据。密码从不写入浏览器存储，访问凭据
只放在当前应用进程的内存中，默认 15 分钟失效。刷新凭据在服务器数据库中只保存摘要；即使
直接读取数据库，也不能取得浏览器中原始凭据。

Flet Web 使用浏览器的持久化偏好存储实现这一行为。它在使用体验上相当于网站的“保持登录”，
但不是保存用户名和密码的自动填充功能。

桌面版不使用浏览器存储，而是把同一种刷新凭据交给操作系统密钥环：Windows 使用系统凭据
存储，macOS 使用钥匙串，Linux 使用当前桌面环境提供的 Secret Service。桌面应用同样不会
保存密码。

## 公用电脑的处理

在教室、公用办公室或借用设备上使用后，必须从右上角用户菜单点击“退出登录”。只关闭页面
不会退出，这是“保持登录”功能的正常行为。如果忘记退出，可让系统管理员停用账号后再启用，
或重置密码；这两种操作都会使旧刷新凭据失效。

不要把浏览器用户目录、桌面密钥环或已经登录的系统账号共享给其他人。

## 验收方法

在测试账号和测试数据库上按以下顺序检查：

1. 登录并完成首次改密，确认进入工作台。
2. 硬刷新页面，确认仍在工作台。
3. 关闭标签页，在同一浏览器中重新打开系统，确认仍在工作台。
4. 重启 Flet Web 服务，不清除浏览器数据，重新访问并确认仍在工作台。
5. 从用户菜单退出，刷新页面，确认只显示登录页。
6. 检查浏览器中没有保存密码；检查服务日志中没有打印登录凭据。

仓库中的 `tests/client/test_api_client.py` 检查新页面能读取已保存的刷新凭据以及退出后删除
凭据。真实浏览器验收截图保存在 `docs/verification/ui/`，截图中不包含密码或凭据。
