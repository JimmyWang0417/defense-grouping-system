# 名词说明

本页只解释手册和页面中会看到的词。业务操作不要求理解程序实现。

| 页面或文档中的词 | 这里的具体含义 |
| --- | --- |
| API | 客户端和后端服务交换数据的接口。看到“API 未启动”时，可以理解为客户端连接不到后端服务。 |
| SQLite | 保存在单个文件中的数据库，适合本机和课程演示。 |
| PostgreSQL | 独立运行的数据库服务，适合服务器和多人使用。 |
| 数据库迁移 | 按版本修改数据库表结构。项目用 Alembic 执行这些修改。这里的“迁移”不一定表示把数据搬到另一台机器。 |
| 检查（预检） | 读取上传文件并列出错误，但不写入正式数据。只有“确认导入”才会写入。 |
| 事务 | 一批数据库操作要么全部成功，要么全部取消。导入中途失败时不会留下前半批数据。 |
| 必须满足的条件（硬约束） | 不能直接违反的排组要求，例如导师回避、时间不冲突和教室容量。 |
| 排序权重（软约束权重） | 在多个都合格的方案中决定优先顺序的数字，不会放宽必须满足的条件。 |
| 例外 | 对某一活动、某一对象和某一种冲突的明确放行。例外有审批人和到期时间。 |
| 草稿 | 可以继续调整、尚未对教师生效的方案。 |
| 准备完成 | 已通过检查、可以发布的方案。 |
| 发布 | 把方案设为当前正式安排。教师只看到已发布安排。 |
| 归档 | 保留旧方案供查询，但不再把它当作当前安排。 |
| 撤回 | 停止使用当前发布方案，但不删除历史数据。 |
| 审计记录 | 系统保存的操作记录，用于查询谁在何时修改了什么。 |
| 随机种子 | 一个用于重复排组过程的整数。同一输入和同一种子更容易得到相同结果。 |
| 请求编号 | 每次 API 请求的识别号码。报告问题时可用它查找对应日志和审计记录。 |
| token | 登录或调用外部服务使用的访问凭据。它和密码一样不能公开。 |
| Pull Request | GitHub 上把一个分支的修改申请合并到 main 的页面，本手册称为“合并申请”。 |
| PR Gate | GitHub 合并前的总检查名称。格式、测试、PostgreSQL 和 Web 构建全部成功后，它才成功。 |
| ruleset | GitHub 的仓库规则集合，用来要求 main 必须经过合并申请和 `PR Gate`。 |
| Release | GitHub 上带版本号的发布记录，包含变更说明和可下载文件。 |
| wheel、source archive | Python 安装包和源代码压缩包，主要用于部署后端或继续开发。 |

如果页面出现本表没有的词，请在问题报告中附上页面名称和原文，不要只写“系统报错”。
