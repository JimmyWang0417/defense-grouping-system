# 角色与权限

系统有三种角色。权限按角色和院系同时判断，不是只看菜单是否显示。

## 系统管理员

系统管理员负责全局设置，可以：

- 创建、修改、停用院系；
- 创建用户并分配角色；
- 重置或停用账号；
- 查看所有院系的系统级信息；
- 完成本机初始化和服务器维护。

系统管理员不应代替教务管理员处理每一次普通排组。日常业务使用院系范围的账号，更容易判断操作责任和数据边界。

## 教务管理员

教务管理员只处理被授权院系的数据，可以：

- 维护专业、方向、教师、学生、学期、课程占用、请假、教室和答辩活动；
- 下载 Excel 模板，检查并确认导入；
- 设置活动规则、时段和可用教室；
- 提交排组任务，查看结果，复制和调整方案；
- 申请例外；在另有授权时审批其他人提交的例外；
- 检查、发布、撤回和导出方案；
- 查询本院系的审计记录。

同一个账号可以被授权多个院系。执行导入等操作时，如果系统无法唯一判断院系，页面会要求明确选择。

## 教师

教师账号用于查看和确认个人安排，可以：

- 查看自己参加的已发布答辩；
- 查看每项安排的时间、教室、学生和同组教师；
- 确认自己已收到安排。

教师不能查看其他教师的完整个人安排，不能修改主数据，也不能发布方案。

## 例外审批为什么需要两个人

有些实际情况可能需要放行一项原本不允许的冲突，例如经过确认后允许某位教师在特殊情况下超出工作量。申请人不能审批自己的申请，审批人还必须：

- 账号处于启用状态；
- 有权访问该答辩活动所属院系；
- 被授予例外审批权限。

审批只对申请中写明的对象和条件有效。例如，针对“教师甲与学生乙的导师回避”批准的例外，不能用于其他教师、学生或其他类型的冲突。

## 常见权限提示

| 页面提示或代码 | 含义 | 处理方法 |
| --- | --- | --- |
| `forbidden` | 当前角色不允许执行该操作 | 换用正确角色；不要通过共享管理员账号解决 |
| `department_scope_denied` | 数据不属于账号授权院系 | 核对当前院系，必要时由系统管理员调整角色范围 |
| `password_change_required` | 临时密码尚未修改 | 先完成改密，再访问其他页面 |
| `self_approval_forbidden` | 申请人试图审批自己的例外 | 由另一名有审批权限的教务管理员处理 |

停用用户后，该用户不能继续登录。历史审计记录和已发布方案仍会保留，不会因账号停用而删除。
