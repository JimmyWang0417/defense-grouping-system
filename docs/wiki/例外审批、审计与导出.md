# 例外审批、审计与导出

## 什么是例外

系统把以下条件作为不能直接违反的条件：

- 导师不能参加自己学生所在的答辩组；
- 学生或教师有课程占用时不能安排；
- 学生或教师请假时不能安排；
- 教师不能超过活动设置的工作量上限；
- 同一个人或教室在同一时间不能重复安排；
- 组长职称、组人数、教师人数和教室容量必须满足规则。

前四类可以在有充分理由时申请准确范围的例外。重复安排、组长资格和教室容量等条件不能通过宽泛审批绕过。

## 提交例外申请

进入“例外审批”，选择活动和条件类型，并根据类型填写对象：

| 条件 | 需要填写的对象 |
| --- | --- |
| 导师回避 | 教师和学生 |
| 课程冲突 | 人员和时段 |
| 请假冲突 | 人员和时段 |
| 工作量上限 | 教师 |

还要填写：

- 原因：10 至 1000 个字符，说明为什么业务上确实需要放行；
- 到期时间：到期后不能用于新的排组或发布检查；
- 所属活动：例外不能跨活动使用。

原因应写事实，例如“经学院确认，该课程本周停课并附审批单编号”。不要写“特殊情况”“领导同意”这类无法核对的内容，也不要写密码或 token。

## 审批、拒绝和撤销

审批人必须是另一名有权限的教务管理员。处理前应核对：

1. 申请对象是否准确；
2. 理由是否能由线下材料证明；
3. 到期时间是否覆盖所需日期且不过长；
4. 是否有不使用例外的可行安排；
5. 申请人和审批人是否属于该活动院系。

审批后，系统只在后续检查中允许该项冲突。已经发布方案会保存当时使用的审批信息，便于以后说明。

撤销会阻止例外继续用于新的检查，但不会改写过去已发布方案的历史记录。发现审批范围错误时，应撤销并重新提交准确申请。

## 审计记录

审计记录用于回答“谁在什么时间对哪个对象做了什么”。记录包含：

- 操作人；
- 操作名称；
- 对象类型和对象编号；
- 请求编号；
- UTC 时间；
- 处理前后的简要信息。

密码、密码摘要、token、刷新 token 和 JWT secret 会在写入前去掉或遮盖。审计记录只允许追加，业务页面不提供修改和删除。

查询问题时，可以先用页面响应中的请求编号搜索审计记录，再按对象和时间缩小范围。

## 导出发布方案

只能从已经保存的方案导出，导出不会重新运行排组。发布方案的 Excel 包含：

- `分组总表`：每组的学生、教师、组长、时段和教室；
- `教师安排`：按教师查看任务；
- `学生安排`：按学生查看任务；
- `教室时段`：按教室和时间查看占用；
- `冲突与例外`：方案中使用的已批准例外；
- `方案信息`：活动、版本、状态、生成时间和分数等信息。

导出后检查文件中的方案版本和系统当前发布版本是否一致。重新发布新版本后，应重新导出，旧文件应标注“已失效”或移入历史目录。

Excel 中包含师生信息。发送时使用学校批准的文件渠道，并限制接收人。不要把真实导出文件提交到 Git 仓库。

## 撤回与归档

发现已发布方案不应继续使用时，可以撤回或归档。操作不会删除方案和审计记录。随后应：

1. 通知已经收到安排的教师；
2. 说明哪个版本停止使用；
3. 从旧方案复制新草稿；
4. 完成调整、检查和重新发布；
5. 发送带新版本号的导出文件。
